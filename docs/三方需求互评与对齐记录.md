## 二、第一轮：逆向需求转述

### AI-A 转述摘要

来源：`AI-A需求转述与技术方案.md`

产品不是「一个行程规划网站」，而是 **会自己干活的调研工厂**：顾问提交自然语言需求后，8 个 Agent 自动完成解析 → 拆解 → 抓网页 → 舆情 → 排日程 → 算预算 → 出报告。人只在风险挂起时审批，以及通过 `travel_plan.md` 看进度。

核心设计哲学是 Manus 式 **文件即大脑**：进度、中间结果、断点全部持久化到 Markdown；`kill -9` 后 5 秒内可续跑，且人可读文件做可解释性。

工程本质是 **长周期异步任务编排**（业务皮才是文旅行程）。硬指标（QPS 200 / P95 300ms / 错误率 0.1%）只约束 **同步接口**（创建入队、查状态），不能要求 Agent/LLM 流程本身 300ms 跑完。

**AI-A 技术倾向：** LangGraph；Redis Streams；DB 为对外权威、文件为台账 + 断点；JWT；5 张核心表；MVP 单 Worker；开发/压测 Mock LLM；种子 URL 为主。

**AI-A 抛出的 10 个待拍板点：** 真 LLM vs Mock；真抓取 vs 种子；状态权威源；5 秒计时起点；HITL 时 Worker 阻塞 vs 释放；超预算 20% 基数；审批超时；QPS 口径；单/多 Worker；`travel_plan.md` 每行程一文件 vs 全局一份。

### AI-B 转述摘要

来源：`architecture-design.md` v0.1 §1

一句话：多 Agent 文旅行程规划系统——用户输入偏好，8 个 Agent 按 DAG 产出个性化行程与预算；全过程以 workspace 状态文件做 planning-with-files 持久化；支持崩溃后断点续传；超预算 20% / 高危夜行 / 严重舆情时 HITL。

拆为四个能力：① 8 Agent 固定拓扑编排；② 文件化持久化 + 断点续传；③ FastAPI + Redis Streams + JWT/RBAC + Compose，五状态机 + 原子写文件；④ HITL 与网页安全过滤 / Prompt 注入防御。

**AI-B 理解边界：** 行程规划是分钟级长任务，性能指标只能约束提交/查询/审核等轻量同步接口。

**AI-B 技术倾向（评审前）：** 自定义轻量 DAG（借鉴 LangGraph 模型、不引依赖）；Redis Streams + PEL/XAUTOCLAIM；Redis 热状态 + Markdown 快照分层；JSON+Pydantic、禁用 pickle；审核 Lua CAS；前端 React + **SSE**；JWT access+refresh；曾考虑 roles 表与 MinIO。

### 双方提出的异常点清单

| 序号 | 异常点 | 提出方 | 严重程度 | 学生裁决 |
|---|---|---|---|---|
| 1 | `travel_plan.md` 并发写入损坏 | AI-A | 高 | 采用原子写入 + 哈希校验：temp → fsync → **`os.replace`** → 目录 fsync；写前快照最近 5 版；**`.tmp` 不是备份**（采纳 AI-B 对 AI-A 初版 rename/回退 `.tmp` 的事实纠正） |
| 2 | LLM API 速率限制 | AI-A | 中 | 三级降级：指数退避（1s/2s/4s，最多 3 次）→ 缓存/规则降级并打 `quality=degraded` → 挂起/失败，**禁止静默丢弃** |
| 3 | 网页 Prompt 注入攻击 | AI-A 提出、AI-B 强化 | 高 | **结构隔离为主**（数据/指令分离 + `<web_content>`）+ 规则引擎前置 + 工具白名单沙箱（仅 fetch/search）+ 输出侧 sanitize；拦截写入 `audit_logs`（`security_block`）。有害内容过滤与注入检测拆成两个模块 |
| 4 | 断点状态检测可靠性（写一半崩溃） | AI-A | 高 | 半成品永不当成品；`resume_from` 在 task 持久化成功后推进；恢复时文件 checksum 自检 + 快照回退 + Checkpointer 对齐；已 `completed` 的 task 不重跑 |
| 5 | 高并发重复审批 | AI-A 提出锁+DB 兜底；AI-B 改为 CAS | 中 | **Lua CAS（Suspended→Reviewing）** 抢占 + 5 分钟可续期租约锁；DB `decision=pending` 条件更新为正确性保证；**不用 10s 短锁当正确性** |
| 6 | 三套状态源漂移（DB / 文件 / Redis Checkpointer） | AI-B 评 AI-A（T3/T4/E4） | 高 | **分层单一职责**：DB = 对外展示权威；`travel_plan.md`（含 `resume_from`）= 恢复驱动源；Redis = 热缓存 + Checkpointer + 锁/队列。同 Worker 单点顺序写，冲突时文件 version 回写 DB |
| 7 | 单 Worker 下 XAUTOCLAIM 无法「他人接管」 | AI-B | 中 | MVP 单 Worker 接受；崩溃恢复 = 进程重启后 `recover_all()` + 自认领 PEL；5 秒口径定为 **Worker 就绪后 5 秒内 resume** |
| 8 | LLM 非幂等导致「重做最后 task」结果漂移 | AI-B（T10） | 高 | 恢复只重跑 **尚未持久化结果** 的 task；`completed = 已落库且已落文件 = 不重跑` |
| 9 | 队列无背压，LLM 慢时 pending 打爆内存/账单 | AI-B（T9） | 中 | Stream `MAXLEN` + Worker 内 LLM 信号量（默认并发 1）+ 队列深度监控告警 |
| 10 | 重复提交（连点创建两个 plan） | AI-A 评 AI-B（#17） | 中 | `Idempotency-Key` + `submit_lock:{user_id}` 5 秒防抖 |
| 11 | 审核超时导致挂起堆积、状态机无出口 | AI-A（D7） | 中 | 默认 24h 可配，超时 **自动终止（视为驳回）并记录/通知**，MVP 不升级 |
| 12 | HITL 阻塞 Worker 导致池饿死 | AI-A（D5），双方同意 | 高 | 挂起后 **释放 Worker 并 ack**；审批通过 **重新入队续跑** |
| 13 | Web Research ∥ Sentiment 并行的数据依赖错误 | AI-A 评 AI-B（#11） | 高 | **必须串行**：全部抓取完成后再舆情分析 |
| 14 | Docker 冷启动超过 5 秒 vs 恢复 SLA | 双方 | 中 | 恢复 SLA **不含** 整机冷启动；Compose 健康检查拉起后，再计 5 秒 resume |

## 三、第二轮：交叉评审

### AI-B 评审 AI-A 方案的关键意见

来源：`AI-B评审意见.md`

**总体：** 在 7 人日 + 验收演示前提下，AI-A 的 LangGraph / Mock LLM / 单 Worker **务实可辩护**。实质不同意见集中在 **恢复真相源单一化** 和 **原子写两处事实错误**。

| 类别 | 要点 |
|---|---|
| 同意 / 已定 | Redis Streams；HITL 释放 Worker；超预算以用户预算为基数（须可配）；per-plan 文件；Mock LLM；种子 URL |
| 部分同意 | LangGraph：有经验则省时，无经验则 7 人日可能被框架踩坑拖死（交学生裁） |
| 反对 / 纠正 | `travel_plans.resume_from` 无对账的双保险是双真相；Windows 下 `os.rename` 不能覆盖，须 `os.replace`；rename 后应目录 fsync；回退读 `.tmp` 不成立（tmp 是写了一半的临时文件） |
| 遗漏 | 并行与否未论证；缺 reports/audit、attempt/cost 字段；缺 refresh 流（后由学生砍）；错误率无口径；**未指定 LLM 供应商**；QPS 达标 ≠ plan 吞吐 |
| 安全 | 网页有害内容过滤 ≠ Prompt 注入，须拆模块 |
| 最高优先级请学生拍 | ① 端到端吞吐 ② LLM 供应商 ③ 5 秒恢复含义 ④ 恢复真相源 ⑤ LangGraph vs 手写 |

### AI-A 评审 AI-B 方案的关键意见

来源：`AI-A对AI-B方案的交叉评审意见.md`

**总体：** 工程成熟度高。明确 **采纳**：`os.replace` + 目录 fsync + version header；PEL/XAUTOCLAIM；Lua CAS；禁用 pickle；错误码 40/41/50/60 分段；Failed 终态。

**不同意或问题（9+ 处）：**

| # | 意见 |
|---|---|
| 1 | 「LangGraph 不适合 QPS 200」不成立——编排不在压测路径上；自研 Checkpointer 是正确性地基，7 人日出 bug 无框架兜底。建议保守选 LangGraph |
| 2 | Redis 自称「热状态真相源」是 **根本分歧**：Redis 可丢，且与文件断点双真相 |
| 11 | Web Research ∥ Sentiment **数据依赖错误，必须改串行** |
| 7–10 | React Flow、MinIO、refresh token、roles 表 = **MVP 过度设计，建议砍** |
| 13 | 驳回回 Planning rework 测试面太大，MVP 应 **终止** |
| 14 | 缺 `Cancelled` 终态（有 cancel 接口却无状态） |
| 16 | 必须恢复 `budget_records` |
| 18 | supervisor 能否自审未定义 |
| 22 | 工单只要 **task/网页级** 恢复，step 级是加分项 |

AI-A 给出 D1–D15 **建议裁决包**，作为学生一次性拍板清单。

### 争议点与最终裁决

| 序号 | 争议点 | AI-A立场 | AI-B立场 | 学生最终裁决 | 裁决理由 |
|---|---|---|---|---|---|
| 1 | LangGraph vs 自定义 DAG | LangGraph；7 人日不重造轮子；编排不在 QPS 路径 | 初版自定义 DAG（白盒、贴合文件、零锁定）；评 AI-A 时改为「有经验用框架、无经验可手写」 | **LangGraph** | 工单首选项；工期保险；拓扑固定 8 节点足够用框架 |
| 2 | 权威状态源 | DB 权威，文件台账 | Redis 热真相 + 文件 durable 快照 | **分层：DB 展示权威；文件（含 resume_from）恢复驱动；Redis 缓存/Checkpointer** | 避免三真相；工单场景二明文读文件 `resume_from` |
| 3 | 是否保留 DB `resume_from` | 冗余双保险 | 反对，易 stale | **保留，且与文件同事务/同 version 更新，文件为准** | 列表查询需要；无对账则禁止只改一侧 |
| 4 | Sentiment 时序 | 串行（评 AI-B 时纠正） | 初版并行 fan-out | **串行** | 舆情输入依赖抓取正文，并行是数据依赖错误 |
| 5 | 驳回语义 | MVP 终止，rework 二期 | 初版回 Planning rework | **驳回终止**（`completed` + `rejected=true`） | 7 人日装不下二次规划；顾问可复制新建 |
| 6 | 实时推送 | 初版 WebSocket，后接受 SSE | SSE 更简 | **WebSocket `/ws/plans/{id}`**（定稿接口按任务模板锁死） | 与说明书第七章一致；事件可单向推送 |
| 7 | JWT | 仅 login，可省 refresh | access+refresh | **单 access，TTL 24h，砍 refresh** | 验收无要求，省工期 |
| 8 | RBAC 模型 | 两角色字符串列即可 | roles + permissions JSON | **`users.role` 枚举 advisor/supervisor** | 两角色无需权限矩阵 |
| 9 | 文件存储 | 未强调对象存储 | 本地卷 vs MinIO 待定 | **Docker 本地卷，砍 MinIO** | 单机 MVP 足够 |
| 10 | 前端可视化 | 看板即可 | React Flow DAG | **Ant Design Table + 徽章 + 进度条，砍 React Flow** | 工单只要实时看板 |
| 11 | 5 秒恢复含义 | 倾向从 Worker 进程启动计 | PEL min-idle + docker 重启，5 秒很紧 | **Worker 进程就绪后 5 秒内完成 resume**；冷启动另计 | 否则 Docker 拉起本身超 SLA，指标不可测 |
| 12 | QPS 200 口径 | 主要打 status 查询 | 同步 API，长任务异步 | **同步轻量接口（status 为主）** | 长任务不可能 300ms；须在压测报告写明口径 |
| 13 | 单 Worker vs 多 Worker | MVP 单 Worker | 同意 MVP 单 Worker，指出 XAUTOCLAIM 失效 | **单 Worker**；崩溃靠重启 recover；预留 Group 扩展 | 断点无竞争；7 人日简单 |
| 14 | LLM | 开发/压测 Mock，演示真调 | 必须抽象供应商，初版未指定型号 | **`LLMProvider` 接口；Mock 签名与真 LLM 一致；压测禁止打计费 API** | 成本与稳定性；演示可切真模型 |
| 15 | 网页抓取 | 种子为主，验收真抓一次 | 需数据源/合规清单 | **种子 URL（含正负舆情 + 第 7 页对抗样本）+ 允许一次真抓演示** | 反爬不作为 MVP 稳定性依赖 |
| 16 | HITL 时 Worker | 释放后重新入队 | 同意 | **释放 + ack + 通过后 resume 队列** | 阻塞会饿死 Worker |
| 17 | 超预算 20% 基数 | 用户原始预算 | 同意，须可配 | **用户预算 × (1+阈值)，默认 0.20，环境变量可配** | 符合工单语义 |
| 18 | 审批超时 | 24h 自动终止 | 须明确拒绝还是升级 | **24h 可配，超时 = 自动驳回终止，不升级** | MVP 仅两角色，状态机要有出口 |
| 19 | 恢复粒度 | 文件 task 级（场景二：第 6 页） | 曾建议 ReAct step 级 | **MVP task/网页级**；step 级加分项 | 工单原文是网页粒度 |
| 20 | 状态机终态 | 五态 + 建议 Failed | 补 Failed；AI-A 再补 Cancelled | **五态 + failed + cancelled**；Reviewing 只存在于审核表/Redis，DB 主状态仍为 suspended | 接口与状态机一致 |
| 21 | 核心表 | 5 张（含 budget_records） | 7 张（曾缺 budget 明细） | **5 张核心表 + 必建 audit_logs**；agent_tasks 补 attempt；budget_records 保留 | 预算表是交付物；拦截要可断言 |
| 22 | 审批权限边界 | advisor 创建 / supervisor 审批 | 未定义自审 | **supervisor 不创建行程** | 从根上避免自审 |
| 23 | 提交防重 | 后补 Idempotency | 初版未覆盖 | **Idempotency-Key + 5 秒提交锁** | 高并发防重要覆盖创建，不只审批 |
| 24 | 端到端 plan 吞吐 | 未单列 | 必须补 plans/hour，否则 QPS 被验收打回 | **不承诺 200 plan/s**；监控队列深度与 plans/hour | 单 Worker 处理分钟级任务，与同步 QPS 解耦 |
| 25 | 原子写细节 | tmp+fsync+rename，损坏读 .tmp | os.replace + 目录 fsync；tmp 非备份 | **按 AI-B 纠正实现** | Windows 兼容与断电持久化事实 |

| 序列化 | JSON + Pydantic，禁用 pickle | 三方一致（采纳 AI-B） |

## 五、遗留待确认事项

下列 **不阻塞按定稿开工**，但须在开发/联调中实测并写进 Loop 验证报告；若与验收方口头不一致，以验收方当场确认为准并回写本文档。

1. **压测流量配比**：定稿建议约 80% status + 15% 列表/详情 + 5% 创建。若验收方要求「混合全接口 200 QPS」，需现场改 Locust 权重并重出报告。
2. **`docker kill` 后 5 秒**：包含容器重启时间时可能不够。已将 **resume SLA** 与 **容器 healthy SLA** 分开写；联调须分别计时并如实记录，避免只报一个「5 秒」。
3. **演示用真 LLM 的具体模型名与 Key 管理**：接口已抽象，型号未锁。演示当天再配环境变量即可，禁止写入仓库。
4. **高危夜行细则**：已给默认窗口 22:00–06:00 + 种子 `night_risk` 标签。若验收用真实地理数据，规则可能要调，保持配置化。
