## 一、项目背景

### 1.1 业务背景

传统文旅行业的行程规划，靠**人工查资料 + Excel 排行程**。旅行顾问接到一个需求（比如"7天云南家庭游"），要手动：

1. 上网搜景点、酒店、交通、天气
2. 看景点口碑、避开差评和消费陷阱
3. 逐天排行程、算预算
4. 检查有没有风险（夜行、超预算）

一个行程从需求到方案，往往要**几小时到一整天**，而且：

- **数据是静态的**——查到的信息可能已经过时
- **没有风险拦截**——可能推荐了有严重差评的景点、超预算的行程
- **没有容灾**——查到一半电脑崩了，前面的工作全丢
- **没有个性化**——不管老人还是儿童，行程千篇一律，不会按人群适配

### 1.2 技术背景

这是一个人工智能课程/实训项目的**工单任务**，属于「多 Agent 协同」系列。项目分两期：

- **多 Agent-2（本文主体）**：文旅资源调研与个性化行程规划系统
- **工单 7（叠加）**：跨系统协同共享图记忆与运行态强干预系统

要求用 **LangGraph + 多 Agent** 技术栈，把一个"人工排行程"的场景，改造成"AI 自动调研 + 编排 + 生成"的异步任务系统。

### 1.3 工期约束

- **1 个人**，独立完成
- v1.0 工期 **7 人日**（周一~周五，每天约 1.4 人日折算）
- 工单 7 增量工期 **3 人日**
- 后续持续迭代：人群个性化适配、RAG 检索增强、语音创建、对话式创建等

在这个极紧的工期下，必须做大量**「最小增量、最大复用」**的取舍决策。

## 二、项目痛点

### 痛点 1：语义遗忘（工单 7 点名的核心痛点）

> 用户第 1 次说"我母亲海鲜严重过敏"，系统记住了；两周后用户再来做"青岛游"，系统**忘了**过敏这件事，推荐了一堆海鲜餐厅。

**本质**：传统 Agent 系统**没有长期记忆**，每次对话都是"失忆"状态。用户必须反复重复自己的偏好、约束、过敏史。

### 痛点 2：检查点状态不刷新

> 系统正在跑一个行程，某景点突然"台风停运"，但系统**不知道**，还在按旧信息继续编排，把已停运的景点排进行程。

**本质**：运行中的 Agent 状态是"冻结"的，没有**运行态纠偏**能力。

### 痛点 3：长任务无容灾

> 行程规划要跑几分钟（8 个 Agent 依次执行），跑到一半进程崩了，**前面所有工作全丢**，得从头再来。

**本质**：缺少**断点续传**机制。

### 痛点 4：纯人工，无风险拦截

> 人工排行程时，可能无意中推荐了**有严重差评的景点**、**超预算 45% 的行程**、**夜间高危路段**，没有系统化拦截。

**本质**：缺少**人机协作门控（HITL）**。

### 痛点 5：假数据、假智能

> 早期版本的 Agent 用"写死的种子数据"和"Mock LLM"，看起来能跑，但**景点是假的、路线是假的、推理是假的**，没有真实价值。

**本质**：缺少**真实数据源接入**。

### 痛点 6：无人群适配，行程千篇一律

> 传统系统不管同行的是 65 岁老人还是 5 岁儿童，排出来的行程都一样——老人被推荐去滑雪、儿童被推荐去酒吧、早餐给你排火锅。门票也不按年龄分档，老人该免票的算全价，儿童该半价的也算全价。

**本质**：缺少**人群感知**能力。

### 痛点 7：知识不沉淀，无法"查资料再回答"

> 景区门票优惠政策、地方美食、四季玩法这些"常识"，传统系统要么写死在代码里（改起来要改代码），要么靠 LLM 记忆（会编造、会过时）。

**本质**：缺少**检索增强生成（RAG）**——先查知识库，再基于查到的资料回答。

## 三、项目目标与需求

### 3.1 一句话目标

**把一个"人工排行程"的活，改造成"AI 自动调研工厂"**：输入一句自然语言需求，8 个 AI Agent 自动完成调研、编排、预算、报告，全程真实数据、可断点续传、可人工审核、可长期记忆、可人群适配、可检索增强。

### 3.2 核心功能需求

| # | 需求 | 说明 |
|---|---|---|
| 1 | 8 个 Agent 协同编排 | 偏好解析→任务拆解→网页调研→舆情评估→日程编排→预算计算→人工审核→报告生成 |
| 2 | planning-with-files 断点续传 | 全程持久化到 `travel_plan.md`，崩溃 5 秒内恢复 |
| 3 | 五状态机 + 原子写入 | planning/running/suspended/recovering/completed + failed/cancelled |
| 4 | HITL 人机协作 | 超预算45%/高危夜行/严重舆情 → 挂起人工审核（真实触发，不强制） |
| 5 | 安全 | 内容过滤 + 防 Prompt 注入 |
| 6 | 压测达标 | QPS≥200 / P95<300ms / 错误率<0.1% |
| 7 | 图记忆（工单7） | 跨行程沉淀知识图谱，修复语义遗忘 |

| 10 | 完整行程规划 | 每日三餐餐饮推荐 + 景点图片(可放大) + 营业时间 + 出发/返程日期自动算天数 |
| 11 | 出发地到目的地路线 | 完整往返交通规划：去程/返程方式 + 票价 + 耗时 + 建议出发时间 + 途中建议 |

| 15 | 门票/餐饮价格 | 景点门票 + 餐厅人均 参考价（虚拟，标注参考价） |
| 16 | 真实完成时间 | 行程完成时记录 completed_at，列表展示完成时间 |
| 17 | 兴趣爱好自由填 | 兴趣标签不限固定项，可自由输入任意兴趣 |
| 18 | **人群个性化适配** | 老人/儿童门票按年龄分档、交通按年龄购票、人群过滤、兴趣推荐 |
| 19 | **RAG 检索增强生成** | pgvector + 百炼 embedding + 文旅知识库 + AI 目的地解读 |
| 20 | **语音创建行程** | 左侧栏「语音创建」，浏览器原生语音识别说需求转文字生成行程 |
| 21 | **对话式创建行程** | 左侧栏「对话式创建」，像 DeepSeek 一样 AI 主动引导对话收集需求 |
| 21 | **购票/酒店模式偏好** | 一次性买票 vs 分开买票、一次性订酒店 vs 分开订 |

### 3.3 非功能需求

- 检索 P95 < 150ms、干预成功率 100%（工单 7 红线）
- Docker 一键启动
- JWT 鉴权 + RBAC 权限分离
- 语义向量检索（RAG）响应 < 300ms

## 四、技术难点

### 难点 1：断点续传的正确性

**难点**：进程随时可能崩溃（kill -9），怎么保证"不丢进度、不重复执行"？

**解法**：
- 原子写入：临时文件 → `fsync` → `os.replace` → 目录 fsync，任何时刻崩溃文件要么旧版要么新版，绝不"半份"
- checksum 校验 + 快照回退（保留最近 5 版）
- 幂等恢复：已 `completed` 且已落库的任务不重跑，只重跑无持久化结果的当前任务

### 难点 2：异步队列的崩溃接管

**难点**：Worker 崩了，它正在处理的消息怎么办？

**解法**：Redis Streams 的 consumer group + **PEL（pending entries list）+ XAUTOCLAIM**，崩溃 worker 的未确认消息会被自动认领转给存活 worker。

### 难点 3：审核并发（防重复审批）

**难点**：两个主管同时点"审批通过"同一个行程，怎么防止重复审批、状态错乱？

**解法**：**锁降冲突、DB 条件更新保正确**——
- Lua CAS 抢占（Suspended→Reviewing 原子转换）
- DB 条件更新 `WHERE decision='pending'` 才是正确性保证
- 会话租约锁（5分钟可续期）+ token 校验防误删

### 难点 4：写入-入队竞态（容器化才暴露）

**难点**：API 写入行程后立即入队，Worker 抢在 DB commit 前消费，报"行程不存在"。

**解法**：入队前显式 `await db.commit()`。这个 bug 本地单进程测试**永远发现不了**，只有容器化多进程才暴露。

### 难点 5：图记忆的抽取与检索

**难点**：怎么把自然语言"我香菜过敏"抽成结构化三元组？怎么跨行程召回？

**解法**：
- **真实 LLM 抽取**（不限过敏原白名单，香菜/花粉/青霉素都能识别）
- 三元组 upsert 沉淀（`(src_key,dst_key,relation)` 命中即合并）
- 向量 + 图拓扑双路检索 + Redis 缓存（P95 0.3ms）

### 难点 6：运行态强干预的安全与原子性

**难点**：怎么让主管"改运行中的状态"，既不越权、又不产生并发错乱？

**解法**：HMAC 验签 + nonce 防重放 + SETNX 排他锁 + 三写一事务 + 节点入口应用补丁。

### 难点 7：真实数据接入的坑

**难点**：第三方 API 有各种坑（key 类型、参数格式、限流、编码）。

**解法**（实践中踩过的坑）：
- 高德 `_url` 函数最初忘了拼 params，key 根本没发出去
- 高德偶发 `INVALID_USER_KEY`，需要重试机制
- 百炼 `json_object` 模式要求 messages 里含 "json" 字样，否则 400
- 百炼 embedding 单次 batch 上限是 **10**（不是文档常见的 16），超了报 400
- nginx 缓存容器旧 IP 导致 502，需 Docker DNS 动态解析

### 难点 8：人群感知的门票与购票分档

**难点**：门票/交通票价规则复杂（儿童看年龄+身高二选一、老人看年龄、学生看学历、高铁/飞机规则不同），怎么精确落地？

**解法**：
- 门票：`elder_ticket_discount(age)` / `child_ticket_discount(age, height)` 两个纯函数，按规则分档
- 交通：`transport_ticket_prices()` 按"高铁/飞机"分支处理，逐人算票种（婴儿票/儿童票/儿童优惠票/成人票）
- 规则可配（config 里 age 阈值），不写死

### 难点 9：RAG 的语义向量化

**难点**：原来用 MD5 哈希做"假向量"，只能字符级匹配，"海鲜过敏"和"对虾过敏"召回不到。怎么换真语义向量？

**解法**：
- 换 pgvector 镜像 + `vector` 扩展
- 百炼 `text-embedding-v3`（768 维）OpenAI 兼容 `/embeddings`，复用现有 key
- 分批（batch=10）规避单次上限
- 历史节点重新向量化（backfill）

## 五、项目亮点

### 亮点 1：全链路真实数据

从"假种子数据 + Mock LLM"彻底升级为真实数据：

| 数据 | 来源 | 真实性 |
|---|---|---|
| 景点/酒店/餐饮 | 高德 POI 搜索 | ✅ 真实 |
| 路线/距离/耗时 | 高德路径规划 | ✅ 真实 |
| 天气（实时+预报） | 高德天气 | ✅ 真实 |
| 营业时间/评分 | 高德 `extensions=all` | ✅ 真实 |
| 景点/餐饮图片 | 高德 POI `photos` 字段 | ✅ 真实 |
| 出发地/目的地解析 | 阿里云百炼 qwen3.7-flash | ✅ 真实 LLM |
| 记忆抽取 | 真实 LLM（不限白名单） | ✅ 真实 |
| 语义向量 | 百炼 text-embedding-v3 | ✅ 真实 |
| 交通票价 | LLM 估算（高德不提供票价） | ⚠️ 参考价 |
| 门票/人均价 | 虚拟价格模块（按类型） | ⚠️ 参考价 |

### 亮点 2：规划文件即大脑（Manus-style）

`travel_plan.md` 不只是日志，而是**可解释的断点载体**——人能直接读它了解 Agent 在干什么，机器能读它恢复进度。

### 亮点 3：人群个性化适配（重点）

- **老人门票**：按年龄分档——60-64 半价、65+ 免首道大门票（需身份证原件，免票不含观光车/索道）
- **儿童门票**：6 周岁以下或身高 1.2 米以下免票（二选一）、6-18 半价
- **交通购票**：高铁（6岁以下免票不占座/6-14半价/14+全价）、飞机（婴儿票10%/儿童5折/12+成人）、学生票仅限家校往返
- **人群过滤**：有老人剔除滑雪/登山/雪山等高强度项目、有儿童剔除酒吧/夜店/KTV、家庭模式剔除网吧/足浴
- **兴趣推荐**：按兴趣标签 + 亲子/老人友好加权排序景点
- **餐饮规范**：早餐只吃早餐类（不吃火锅/烤鸭）、三餐跨天不重复

### 亮点 4：RAG 检索增强生成（重点）

- **检索**：pgvector 余弦距离 + 百炼 768 维语义向量
- **知识库**：6 类文旅语料（景点攻略/地方美食/景区政策/四季玩法/交通贴士/住宿贴士），38 个分块
- **生成**：报告里 LLM 基于检索到的原文生成"目的地深度解读"，不编造、有据可查

### 亮点 5：双红线指标大幅超标

| 指标 | 红线 | 实测 | 倍数 |
|---|---|---|---|
| QPS | 200 | 1109 | 5.5x |
| P95 延迟 | 300ms | 35.4ms | 快 8x |
| 检索 P95 | 150ms | 0.3ms | 快 500x |
| 干预成功率 | 100% | 100% | 达标 |

### 亮点 6：工程细节扎实

- 原子写入 + checksum + 快照回退，5 秒恢复
- Lua CAS + DB 兜底防重复审批
- 提交防抖 + 幂等键 + 审批超时 + Worker 心跳
- 密钥安全注入（`.env` 不入 git）

### 亮点 7：容器化验证暴露并修复真实 bug

- 写入-入队竞态（commit 时机）
- nginx 缓存旧 IP → 502（Docker DNS 动态解析根治）
- 百炼 embedding batch 上限（10 而非 16）

### 亮点 8：工单 7 全量落地

图记忆 + 强干预，从数据模型、引擎、API、前端、测试到文档，完整闭环。

### 亮点 9：完整的行程规划体验

- 每日**三餐餐饮推荐**（早餐/午餐/晚餐，真实餐厅 + 地址 + 营业时间 + 图片）
- 景点**真实图片**（可点击放大预览）+ 营业时间 + 评分
- **出发/返程日期**自动算天数
- **人类可读的状态看板**（进度条 + 8 Agent 步骤卡片 + 调研成果统计）

### 亮点 10：精致的前端视觉 + 多种创建方式

- 登录页真实风景壁纸（Ken Burns 缓慢缩放 + 深色遮罩）
- 卡片圆角 + 柔和阴影 + 彩色图标底座
- 品牌名「山海行」统一视觉
- 三种创建方式：**新建行程**（表单）+ **语音创建**（说话转文字）+ **对话式创建**（AI 引导对话）

│ 外部数据源                                                │
│ 高德地图(地理编码/POI/路径/天气)                           │
│ 阿里云百炼 LLM(qwen3.7-flash) + Embedding(text-embedding-v3)│

**分层禁令**：API 进程不执行图；Agent 不持有进程内长期状态；前端不直连 Redis。

## 七、8 个 Agent 详解

| 顺序 | Agent | 职责 | 数据源 | 关键技术 |
|---|---|---|---|---|

| 2 | **Planner** 任务拆解 | CoT 拆解调研任务（景点/公园/博物馆/酒店/餐厅/早餐/快餐/购物/交通） | 真实 LLM | 内置调研维度降级 |

| 5 | **Itinerary** 日程编排 | 按天编排 + 高德路径 + 三餐餐饮 + 人群过滤/兴趣排序 + 门票分档 + 知识库检索 | 高德 API | 路径规划 + 干预补丁读取 |

  → 否则 report（直接出报告）

## 八、核心技术实现

### 8.1 断点续传

- 全程持久化到 `workspace/{plan_id}/travel_plan.md`
- YAML 头含 `version`、`checksum`、`status`、`resume_from`
- 原子写入：临时文件 → fsync → `os.replace` → 目录 fsync
- 快照回退：保留最近 5 版，checksum 失败自动回退
- 崩溃恢复：Worker 启动扫描 running/recovering → 读 resume_from → 跳过已完成任务续跑

### 8.2 状态机

```
planning → running → suspended → completed
              ↓          ↓
         recovering   rejected(驳回)
              ↓
            failed / cancelled
```

### 8.3 HITL 人机协作

三个触发条件（超预算45% / 高危夜行 / 严重舆情）→ 挂起，主管在审核台抢占/通过/驳回。

- 抢占用 Lua CAS（Suspended→Reviewing 原子转换）
- 挂起后 Worker 释放（不阻塞），审批通过重新入队续跑
- 审批超时（24h）自动驳回

### 8.4 图记忆（工单 7）

```
实体抽取 → 三元组 upsert → 向量+图双路检索
```

- 实体抽取：真实 LLM 抽取（支持任意过敏原）
- 三元组：`(User:用户)-[HAS_ALLERGY]->(Food:香菜)`
- 双路检索：向量相似 + 图拓扑 1 跳邻域，Redis 缓存 60s

### 8.5 运行态强干预（工单 7）

```
HMAC 验签 → nonce 防重放 → SETNX 排他锁 → 三写一事务 → 节点入口应用补丁
```

### 8.6 安全

- JWT + RBAC（advisor 创建/查询，supervisor 审核/干预）
- Prompt 注入检测（规则引擎 + 结构隔离 + 工具白名单）
- 网页内容安全过滤（独立模块）
- HMAC 验签 + nonce 防重放（干预接口）

## 九、人群个性化适配

> 这是本项目区别于普通行程规划系统的核心能力：**行程会感知同行人群，按老人/儿童/学生的实际情况做适配**。

### 9.1 老人门票按年龄分档

按"景区老人免票规则"（国有/政府定价 A 级景区）实现：

| 老人年龄 | 首道大门票 |
|---|---|
| 60 岁以下 | 全价 |
| 60 - 64 岁 | **半价** |
| 65 岁及以上 | **免首道大门票** |

**关键规则**：
- 凭证必须是**本人身份证原件**（不看老年证/退休证/照片）
- 免票**只免首道大门票**，观光车/索道/游船/演出/园中园另计
- 阈值可配（`ticket_elder_free_age=65`、`ticket_elder_half_age=60`）

### 9.2 儿童门票按年龄+身高分档

| 条件 | 首道大门票 |
|---|---|
| 6 周岁（含）以下 **或** 身高 1.2 米（含）以下（二选一满足）| **免票** |
| 6 - 18 周岁 | **半价** |
| 18 岁以上 | 全价 |

**关键规则**：免票只针对首道大门票；民营商业景区无强制国标，以景区公示为准。

### 9.3 交通购票按年龄分档

**高铁（铁路）**：

| 年龄 | 票种 |
|---|---|
| < 6 周岁 | 1 位持票成人免费携带 1 名（不占座）；占座或多出的买儿童优惠票（半价）|
| 6 - 14 周岁 | 儿童优惠票（半价）|
| ≥ 14 周岁 | 成人全价 |

**飞机**：

| 年龄 | 票种 |
|---|---|
| 14天 - 2 周岁 | 婴儿票（成人全价 10%，无座）|
| 2 - 12 周岁 | 儿童票（成人全价 5 折，有座）|
| ≥ 12 周岁 | 成人票 |

**学生票**：高铁学生票仅限全日制大中专中小学的家校往返，旅游出行不适用；飞机无学生优惠。儿童/婴儿购票需身份证、户口本或出生证明。

### 9.4 人群过滤与兴趣推荐

- **有老人**：剔除滑雪/漂流/蹦极/登山/雪山/冰川/高原/峡谷等高强度项目
- **有儿童**：剔除酒吧/夜店/KTV/足浴/桑拿/密室/桌游等
- **家庭模式（有老人或儿童）**：夜生活只保留影院/剧场等全家友好型，剔除网吧/酒吧/KTV
- **兴趣标签**：按用户兴趣（自然风光/人文历史/美食/亲子/购物等）对景点打分排序
- **亲子/老人友好加权**：有儿童优先乐园/动物园/科技馆，有老人优先公园/园林/博物馆/古镇

### 9.5 餐饮规范

- **早餐**：只吃真正的早餐/快餐/轻食（包子/粥/豆浆/馄饨/肠粉/米线/饵丝等），不吃火锅/烤鸭/海鲜等正餐
- **三餐跨天不重复**：用"已用餐厅集合"跨天、跨餐次去重
- **早餐/快餐专门调研**：planner 专门搜"早餐""快餐"关键词，高德返回地方特色早餐店（如云南米线/饵丝/鲜花饼）

### 9.6 景点优待备注

行程中，有老人/儿童的景点下会标注该人群的优待政策，例如：

> 🎫 鹿回头风景区：儿童：6周岁以下或身高1.2米以下免首道大门票，6-18周岁半价；老人：60-64周岁半价，65周岁及以上免首道大门票（仅限首道大门票，观光车/游乐项目另计；民营景区以公示为准）

**关键**：明确区分"景点本身免费"和"特定人群优待免票"，不混淆。

### 9.7 创建页人群信息录入

- **成人关系**：情侣/单身/未婚/已婚/家庭/朋友/同事
- **儿童明细**：年龄 + 身高 + 是否占座（可多个）
- **老人明细**：年龄 + 性别（可多个）+ 生活状态（健康/行动不便/需轮椅/慢病需注意/需常休息）
- **学生明细**：学历（小学/初中/高中/中专/大专/本科/硕士/博士，可多个）
- **购票方式**：一次性买票 vs 分开买票
- **酒店预订**：一次性订 vs 分开订

## 十、RAG 检索增强生成

> 本项目实现了完整的 RAG 闭环：**Retrieval（检索）→ Augmented（增强）→ Generation（生成）**。不靠模型死记硬背，而是先查知识库，再把查到的资料喂给模型生成。

### 10.1 技术底座

| 环节 | 实现 |
|---|---|
| 向量存储 | **pgvector**（PostgreSQL 扩展，vector 0.8.6），镜像 `pgvector/pgvector:pg15` |
| 向量化 | **百炼 text-embedding-v3**（768 维，OpenAI 兼容 `/embeddings`）|
| 分批策略 | batch=10（百炼单次 input 上限 10，超了报 400）|
| 检索方式 | pgvector 余弦距离（`<=>`）|

### 10.2 两个 RAG 场景

**A. 个人记忆语义化（升级图记忆）**

原来用 MD5 哈希做"假向量"，只能字符级匹配，"海鲜过敏"和"对虾过敏"召回不到。现在换成真语义向量：

- `GraphNode.embedding` 从 JSONB 换 `Vector(768)`
- 检索走 pgvector 余弦距离
- 实测：检索"海鲜过敏"能召回 `Food:海鲜`（0.67 分），是语义匹配不是字符匹配

**B. 文旅领域知识库（新增）**

`document_chunks` 表存 6 类文旅语料（38 个分块）：

| 语料 | 内容 |
|---|---|
| 景点攻略 | 故宫/长城/西湖/三亚/熊猫基地/张家界/兵马俑/漓江等 |
| 地方美食 | 北京烤鸭/成都火锅/广州早茶/杭帮菜/西安面食/云南米线/三亚海鲜 |
| 景区优待政策 | 儿童/老人/学生优待、免费与优待的区别、餐饮无优待 |
| 四季玩法 | 春季赏花/夏季避暑/秋季红叶/冬季滑雪温泉 |
| 交通贴士 | 高铁/飞机/学生购票规则、市内交通 |
| 住宿贴士 | 带老人/儿童住宿、旺季预订、位置选择 |

### 10.3 RAG 三个环节

| 环节 | 实现位置 |
|---|---|
| **R 检索** | `memory/kb_retrieve.py` 的 `search_kb()`，pgvector 余弦距离召回 top-k |
| **A 增强** | 召回原文 chunk 拼进节点上下文（`web_research` 调研 + `itinerary` 编排两处注入）|
| **G 生成** | `report.py` 的 `_generate_rag_insights()`，LLM 基于原文生成"目的地深度解读" |

### 10.4 生成效果（实测）

报告里新增「目的地深度解读（AI 生成）」章节，例如云南行程：

> "美食方面强烈推荐云南过桥米线，滚烫的高汤现烫食材……早餐也可以换着吃烧饵块、稀豆粉、破酥包……"

> "过桥米线汤温极高，小朋友必须由大人帮忙烫熟……饭店没有国家强制的老人儿童免餐或打折规定……"

**关键特性**：
- **有据可查**：内容来自知识库原文，不编造
- **人群感知**：带入同行老人/儿童信息，针对性提醒
- **降级安全**：非 real 模式或检索为空时返回 None，报告照常出

## 十六、设计决策记录

项目在极紧工期下，做了大量「最小增量、最大复用」的取舍：

| 决策 | 内容 | 理由 |
|---|---|---|
| 编排框架 | LangGraph | 工单首选，7人日不允许自研图引擎 |
| 队列 | Redis Streams | 工单指定，PEL 原生支持断点 |
| LLM | 抽象 Provider，Mock→真实切换 | 压测不烧钱，演示切真模型 |
| 文件布局 | 每行程一目录 | 避免并发写冲突 |
| 恢复粒度 | task/网页级 | 满足验收，ReAct step 级是加分 |
| 图存储 | PostgreSQL 应用层向量→pgvector | 延续单机原则，后续换 pgvector 提升语义 |
| 向量后端 | pgvector（可切 cosine）| 单机原则，不引独立向量库 |
| Embedding | 百炼 text-embedding-v3（768）| 复用现有百炼 key，OpenAI 兼容 |
| 记忆引擎 | 自研轻量 Mem0 风格 | 3人日不允许消化外部框架黑盒 |
| 干预 | HMAC + nonce + 三写事务 | 工单验收红线：安全验签 |
| 门票分档 | 纯函数 + 可配阈值 | 规则可调，不写死 |
| 知识库 | 本地 md + 向量化入库 | 改 markdown 即可更新，不用改代码 |
